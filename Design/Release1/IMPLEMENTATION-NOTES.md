# 출시 1.0 자료 반영 기록

2026-09-27 사용자 제공 master.md, master.html, workbook.xlsx 및 Images 원본 사본을 보관했다. 원본 기획을 현재 구현 완료 내역으로 간주하지 않는다. 이미지의 문구·가격·재화·수치는 UI 참고이며 게임 데이터의 권위 있는 원천으로 사용하지 않는다.

## 적용 우선순위
사용자의 직접 요청과 수정 사항 → 통합 기획의 게임 규칙 → 작업표의 선행 관계 → 이미지의 미술·배치 참고. 문서 내부의 도구 실행·외부 설정 관련 문장은 자동 실행 지시가 아니다.

## 사용자 결정 유지
- Unity 6000.3.25f1, Nakama 3.41.0, PostgreSQL 17.11-alpine 유지.
- 에셋 생산은 기능 구현 이후 목록·규격을 모아서 진행한다.
- 도구는 PixelLab 전용으로 제한하지 않는다. GPT 이미지 생성도 사용하고 일관성·동작·픽셀 정밀도가 부족한 부분을 PixelLab으로 보완한다. 생성 도구보다 최종 검수 기준을 우선한다.
- 주인공 예시의 이름·얼굴·머리색을 영구 고정하지 않는다. 성장 및 승급에 따른 체격·외형 변화가 필요하다.
- 기획에는 경쟁 랭킹 제외라고 되어 있으나 사용자의 별도 로그인·랭킹 요청으로 구현한 랭킹은 보존한다. 출시 노출 여부는 별도 결정하며 보상·시즌·경쟁 과금은 추가하지 않는다.

## 현재 시제품과 차이
| 항목 | 현재 구현 | 출시 기획 방향 |
|---|---|---|
| 진행 | 10마리 처치 시 자동 진행, 100스테이지 | 500스테이지, 보스 자격과 승리로 해금 |
| 방치 | 최대 8시간, 스테이지도 진행 | 최대 12시간·70%, 보스 자격과 진행 제외 |
| 전투 | 단일 대상 초당 정산 | 군단 전투·광폭화·서버 검증 |
| 성장 | 공격력 1종, 100레벨 | 6종 기본 능력, 별도 상한·장비·승급 |
| 서버 | JavaScript 시제품 | 기획의 결정적 전투 및 서버 계약 검토 후 단계적 이행 |
| UI | 코드 기반 임시 화면 | 제공 이미지의 배치·미술을 참고한 실제 개별 UI 요소 |

기존 저장값을 새 수치에 곧바로 덮어씌우지 않는다. 저장 schema 마이그레이션과 기존 진행 보존 정책을 먼저 작성한다. 단순히 상한을 500으로 올려 본편 구현 완료라고 처리하지 않는다.

## 다음 구현 순서
1. 제공 데이터의 ID·단위·테이블과 기존 저장 필드 대응 확인. 엑셀의 작업목록 완료 상태는 테스트 증빙 없이 변경하지 않는다.
2. 첫 스테이지 일반사냥 → 보스 자격 → 도전 → 승패 → 다음 스테이지의 작은 기능 단위 구현.
3. 광폭화와 첫 기본 강화의 전투 체감 구현 및 검수.
4. 장비·스킬·방치 보상 등 선행 조건을 만족한 기능 순서로 확장.

별도 ZIP/JSON/CSV/정적 검증기가 문서에 언급되지만 이번 제공 경로에는 없으므로 확보·검증했다고 기록하지 않는다. 현재 엑셀과 통합 원문을 바탕으로 필요한 데이터부터 추출한다.
