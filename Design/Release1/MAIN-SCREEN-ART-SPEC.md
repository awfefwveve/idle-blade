# 메인 전투 화면 아트 제작 확정안 v1

상태: 제작 기준 확정. 이미지 생성·최종 채택·Unity 적용은 아직 하지 않음.
근거: 출시 기획서 17절의 픽셀 규격과 사용자의 최신 메인 화면 변경 요청. 제작 순서는 최신 요청에 따라 메인 화면부터 진행한다.

## 1. 화면과 제작 범위

- 가로형. UI 배치 기준 1672×941, 안전영역 안에 고정. 월드는 640×360 기준, PPU 32, 타일 32×32. UI 글자는 월드 저해상도 렌더에 넣지 않는다.
- 상단: 초상화·이름·레벨·전투력 영역, 칭호, 재화 4종, 공지·우편·설정. 숫자와 명칭은 데이터로 표시한다.
- 왼쪽: 퀘스트·우편·업적·이벤트와 이벤트 배너. 오른쪽: 장비·무기·방어구·스킬·분노·승급·유물·도감, 전체 접기 화살표.
- 하단: 전투 / 각성 / 던전 / 중앙 스테이지·보스 도전 / 상점 / 소환 / 패스. 별도 로비·전투 화면을 만들지 않는다.
- 방치 보상·장비 소환 카드는 X로 완전히 닫힘. 축소 카드·재열기 버튼 없음. 오늘의 임무는 유지.
- 재화 아래 중앙 상단은 비워 둔다. 임의 배너나 장식으로 채우지 않는다.
- 이번 묶음은 메인 화면 공통 UI, 첫 지역, 주인공, 첫 몬스터·보스, 공통 전투 효과까지. 각성·던전·상점·소환·패스 내부 화면, 나머지 지역, 상품 일러스트는 후속 묶음.

## 2. 화풍 기준

- 거친 부족 판타지. 큰 도끼, 읽기 쉬운 근육 덩어리, 가죽·털·무쇠·낡은 목재. 참고 이미지의 분위기와 장식 문법을 따르되 주인공 얼굴·머리색은 고정 모델로 복제하지 않는다.
- 3/4 측면 캐릭터, 오른쪽을 보는 주인공, 왼쪽을 보는 몬스터. 전투는 X축, Y차이는 시각적 배치만 사용.
- 광원 좌상단. 유채색 외곽선 1px, 근육·금속은 기본 3~4단 명암. 배경은 낮은 대비, 캐릭터와 공격은 높은 대비.
- 기준색: 외곽 #211B20, 어두운 철 #45434B, 밝은 철 #A3A0A0, 목재 #65412E, 가죽 #98633D, 피부 #D99767, 피부 밝음 #F2C18A, 붉은색 #B6322D, 불꽃 #F58B32, 황금 #D9AC58, 상아 #E8D9B8, 배경 청회색 #667D89. 기준색에서 필요한 음영만 파생한다.
- 사진 같은 재질, 흐린 테두리, 무작위 미세 점묘, 과한 금장, 모든 물체의 발광, 손·도끼 형태가 프레임마다 변하는 결과는 채택하지 않는다.
- UI는 어두운 철·가죽 바탕과 절제된 청동 테두리. 선택된 전투 메뉴와 보스 도전만 강한 주황/붉은 강조. 모든 버튼을 동시에 강조하지 않는다.
- 한글은 별도 글꼴 렌더링. 에셋에는 글자·숫자·로고·임의 기호 문장을 생성하지 않는다.

## 3. 출력 규격과 파일 목록

모든 크기는 생성 모델의 요청 크기가 아니라 최종 납품 PNG의 픽셀 크기다. 큰 이미지로 생성한 경우 규격화·수정 후 납품한다. 투명 PNG는 RGBA, 배경 RGB/sRGB. 체크무늬를 투명 배경처럼 그린 이미지는 불가.

## 4. 주인공 성장과 애니메이션

- 기획서의 기본 몸체 작업 영역 80×80, 몸체 높이 56~64px를 유지한다. 무기·성장·광폭 여유 공간을 위해 실제 전달 셀은 128×128로 패딩한다. 그림을 셀 전체에 꽉 채우지 않는다.
- 모든 프레임의 발바닥 중앙은 좌상단 원점 기준 (64,112). 그림이 움직여도 기준점을 바꾸지 않는다. 무기 포함 일반 바운드 최대 112×96, 광폭 최대 128×112.
- 성장 외형은 g01 / g02 / g03으로 나눈다. 몸체 높이 목표 56 / 60 / 64px, 어깨·팔·장비 실루엣도 단계별 강화. 서버 성장 단계에 매핑하며 각성 메뉴와 동일한 시스템으로 임의 간주하지 않는다.
- 1차 생성은 g01 전 동작과 g02·g03 대기 대표컷까지. 후속 단계의 모든 동작은 동일 뼈대·발 위치·손잡이 소켓으로 확장한다. 임시 확대만으로 최종 성장 외형을 대체하지 않는다.
- 대기 4, 달리기 6, 평타 A/B/C 각 6, 피격 2, 사망 6, 함성 6, 도약 6, 착지 4, 승리 4프레임. 동작별 가로 시트, 프레임 사이 여백 없음.
- 주인공 몸체와 도끼를 분리한다. 프레임별 손잡이 x/y·회전, 타격 프레임, 루프 여부를 메타데이터로 기록한다. 몸체에 무기를 함께 그린 시트를 최종 교체용으로 채택하지 않는다.
- 군집몹: 발 기준 (24,44), 대기 4 / 이동 6 / 공격 6 / 피격 2 / 사망 6. 보스: 발 기준 (64,112), 같은 동작별 프레임 수.
- 대기는 6fps, 이동은 10fps를 초기 재생값으로 사용. 공격 프레임은 실제 공격 간격에 맞춰 재생하며 그림 프레임 수로 서버 공격 횟수를 결정하지 않는다.

## 5. 교체 계약

- 폴더: Art/Main/UI, World/Region01, Characters/Hero/g01, Enemies, Effects. 파일 ID를 유지하고 버전은 카탈로그에서 관리한다.
- 카탈로그 필수값: assetId, file, width, height, frameCount, pivotPx, fps, loop, sockets, hitFrames, nineSliceBorderPx. 적용하지 않는 필드는 비운다. 픽셀 좌표는 좌상단 기준이며 Unity 피벗은 변환한다.
- Point 필터, mipmap 없음, 캐릭터 PPU 32, 투명 가장자리 검수. 아틀라스 패딩 4px 및 가장자리 확장 2px. 스프라이트 시트 최대 4096px.
- UI 테두리는 9-slice, 삽화는 비율 유지, 아이콘은 공통 크기로 배치. 이미지 원본 크기가 버튼 터치 크기를 결정하지 않는다. 터치 목표는 실제 기기에서 48dp 상당 이상.
- 배경은 좌우 심리스 연결을 실제 반복 화면에서 검사한다. 현재의 좌우 반전 반복은 최종 제작 기준이 아니다.
- 현재 ArtTheme의 128px 임시 스트립과 직접 텍스처 표시 방식만으로 이 계약이 모두 지원되는 것은 아니다. 최종 에셋 적용 때 카탈로그·소켓·9-slice 및 월드/UI 분리 로더를 연결해야 한다. 현 시점에 파일만 덮어쓰면 모두 동작한다고 간주하지 않는다.

## 6. 제작·채택 순서

1. 먼저 기준 샘플 5종: g01 대기 1프레임, 도끼, 군집몹, 첫 지역 배경, 공통 버튼. 같은 화면에 배치해 크기·색·픽셀 밀도를 맞춘다.
2. 채택된 샘플과 팔레트를 모든 후속 생성의 참조로 사용한다. 텍스트 프롬프트만 반복해 통일성을 보장하지 않는다.
3. 공통 UI 전부와 배경 레이어 제작 → 주인공·적 애니메이션 → 효과와 카드 삽화 → 실제 메인 화면 적용 순서.
4. GPT 이미지 생성으로 기준 그림·배경·삽화를 제작할 수 있다. 연속 동작·소켓 일관성이 부족한 것은 PixelLab 또는 프레임 수정으로 해결한다. 생성 도구가 달라도 납품 규격은 동일하다.
5. 채택 검사: 실루엣/손/도끼 일관성, 투명 테두리, 발 미끄러짐, 배경 반복 이음새, UI 텍스트 가독성, 40마리 상황에서 피아 식별, 성장 및 광폭 바운드. 생성 성공만으로 채택 처리하지 않는다.

이번 단계는 규격 확정까지다. 새 에셋을 생성하거나 게임에 적용한 상태는 아니다.
