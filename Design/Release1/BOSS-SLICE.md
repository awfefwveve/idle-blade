# 보스 진행 첫 구현

## 구현 범위
- 기존 stage를 현재 사냥터로 유지. 최고 클리어는 highestCleared.
- 1스테이지 15, 2~10은 25, 이후는 40처치에서 수동 보스 도전 가능.
- 일반 처치만으로 스테이지가 오르지 않음.
- 보스 제한시간 30초. 서버가 시간·공격·승패·최초 골드 보상을 확정.
- 보스전 중 강화 금지. 동시 사망은 실패, 마지막 초에 보스만 사망하면 승리.
- 실패·시간 초과·연결 중단은 자격 유지. 자동 재도전 없음.
- 승리 시 최고 클리어 및 다음 사냥터 갱신, 처치 게이지 초기화. 최초 보상 중복 지급 차단.
- 재접속 정산은 최대 12시간·골드 70%, 보스 자격/스테이지 진행 제외. 소수 골드는 1/10 단위 잔여값으로 보존.

## 호환과 백업
schema 1→2: 골드·레벨·현재 스테이지·처치 수 보존. 과거 최고 클리어는 기존 stage-1로 취급하는 시제품 호환 정책이다. 실제 보스 클리어 증거가 있었음을 의미하지 않는다.
서버 저장 시 progress_backup/schema1에 이전 원본을 최초 1회 보관하며 진행 저장과 같은 storageWrite 묶음으로 제출한다.
배포 전 PostgreSQL 덤프는 작업 폴더 work/before-boss-schema2.dump에 보관했다.

## 아직 임시인 부분
- 이번은 기존 1초 전투 시제품에 진행 흐름을 붙인 단계다. 기획의 50ms 전투 코어·군단·지역 패턴·500스테이지를 완성한 것이 아니다. 현재 상한은 100 유지.
- 보스 HP=기존 일반 HP×5, 보스 공격=최소 8 또는 일반 HP/4, 주인공 HP=250, 최초 보상=100×스테이지. 출시 콘텐츠 테이블을 연결하기 전 임시값이다.
- 원래 일반전투 공격력/강화 공식 유지. 보스 외형은 기존 임시 몬스터, 별도 아트 미생성.
- 온라인 판별은 재접속 resume와 5초 초과 동기화 공백 기준이다. 짧은 네트워크 공백의 정확한 접속 판정이나 다중기기 단일 세션 강제는 후속 과제다. 끊긴 보스전은 안전하게 실패 처리한다.
- 오프라인 70%는 기존 단일대상 시뮬레이션의 골드 기준. 최종 장비/스킬별 방치 산정과 보상 요약은 후속 과제.
- Unity 실제 화면 조작·모바일 검수는 아직 수행하지 않았다.

## 검증
경제·보스 단위 테스트 14개, C# 컴파일, 로컬 실제 서버 로그인·랭킹 회귀 검사. boss-smoke.cjs는 실제 시간으로 자격 획득과 승리 후 2스테이지 해금을 확인한다.

로그인 보완: 실행 중 메모리의 refresh token으로 만료된 access token 갱신 후 동기화. 비밀번호·토큰 디스크 저장 없음. 앱을 종료한 뒤 이메일 자동 로그인은 별도 구현 대상.
